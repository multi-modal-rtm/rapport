# Draft number audit — docs/SECTION_3_DRAFT.md, docs/SECTION_4_DRAFT.md

Every numeric claim in both drafts, checked against `paper_assets/tables/`
(regenerated by `scripts/regenerate_all_tables.py`) and, where a claim
isn't one of the seven regenerated tables, against the underlying stored
JSON/markdown artifact directly (cited per row). Report only — the drafts
themselves are not edited.

## MISMATCHES — flagged loudly, read this section first

**1. Section 4.5's fusion-weight-norm claim is CONTRADICTED by the only
stored analysis that computed it.** The draft states the norms "indicate
active suppression of the non-textual inputs." The actual stored artifact
(`outputs/n4r_step1_diagnostics.json`, `step_1d_fusion_weight_norms`,
sourced from `docs/PHASE_N4R.md` §1d) shows an almost perfectly even
34.4%/32.3%/33.3% (text/audio/video) column-norm split, and the source
doc's own written conclusion is the opposite of the draft's claim: *"the
fusion layer does not appear to have discovered `down-weight the weaker
modalities' on its own... no evidence of learned modality suppression."*
**This is not a missing citation, it's a factual reversal — the sentence
needs to be rewritten or removed, not just have a number dropped in.**

**2. Section 4.3's "$-0.0048$... over the fine-tuned anchor" mis-describes
what that number is measured against.** The value $-0.0048$ is real and
exactly reproducible — but it is `full_R` **minus `base_fusion_R`** (the
graph-free residual baseline), not `full_R` minus the **text anchor**
(`full_R` minus text anchor is $-0.0060$, a different, nearby but
distinct number — see table row below). Section 3.2 uses the same
$-0.0048$ value correctly (there it's explicitly framed as "versus
baseline," i.e. `base_fusion_R`) — the error is localized to 4.3's
"anchor" wording.

**3. Two small, non-decision-relevant rounding/count discrepancies**:
"1,433 multi-party dialogues" (actual, this repo's processed data:
**1,432** — a one-dialogue difference, likely published-count vs.
post-bad-clip-exclusion count, not stated as such); "48.2%" neutral share
of the MELD test set (actual: **48.1%**, 1,256/2,610 — a 0.1-point
rounding difference, not substantive).

Nothing else below rises to "mismatch" — the remainder is either an exact
match, a resolved `[CHECK]`, or a claim with no in-repo artifact (flagged
as such, not silently passed).

## Summary

- **3 mismatches**, one substantive (fusion-weight-norm claim reversed —
  needs a prose fix, not a citation), one a comparator mislabel ($-0.0048$
  described as "vs. anchor" when it's "vs. baseline"), one cosmetic
  (dialogue count / neutral-share rounding).
- **5 `[CHECK]` markers resolved** with real numbers from stored artifacts
  (train-val gap source, minus_relational_R vs full_R direction, n=5/7
  asymmetry, the "macro-oriented F1" mislabel, the fusion-weight-norm
  citation — the last of which resolves into mismatch #1, not a clean
  citation).
- **1 `[CHECK]` confirmed genuinely not-in-record** (the weighted-F1-
  selection robustness re-scoring) — would require a new training
  campaign, not run in this pass.
- **4 external-literature numbers** (SocialArcNet 0.62, DialogueRNN,
  MMGCN, EmoShiftNet) have no in-repo artifact by nature (they're
  citations to outside papers) — flagged with the specific caveat that
  this repo's own SocialArcNet reproduction attempt failed (0.3765 vs.\
  the cited 0.62), which bears on how safely 0.62 can be used for
  calibration without a disclosing footnote.
